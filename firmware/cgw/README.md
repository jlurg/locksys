# LockSys CGW firmware

| Field | Value |
|---|---|
| Component | Central Gateway (CGW), ESP32-S3-DevKitC-1 v1.1 (N8R8) |
| Toolchain | ESP-IDF v5.5.5, `espressif/idf:v5.5.5` pinned by digest in `tools/versions.env` |
| Architecture | [LS-CGW-SAD-001](../../docs/04_software/cgw/architecture.md) |
| Requirements | [LS-CGW-SRS-001](../../docs/04_software/cgw/software_requirements.md) |
| Contract | [LS-SAIC-001 v0.2](../../docs/02_system/LS-SAIC.md) |
| Status | M0 skeleton: portable core implemented and host-tested; adapters build, target verification at M3 |

## Purpose

The CGW bridges the APP protocol 1.0 (SoftAP, WebSocket `/ws/v1`, protobuf frames with HMAC tags) and CAN matrix 1.0 (TWAI, E2E-protected frames). It never drives an actuator; the DCU re-checks every start condition.

## Layout

```text
firmware/cgw/

├── sdkconfig.defaults         common configuration
├── sdkconfig.defaults.dev     DEV variant (fault injection, console, verbose logging)
├── sdkconfig.defaults.release RC/RELEASE variant (no fault injection, WPA3 only)
├── partitions.csv             8 MB: nvs, otadata, nvs_keys, efuse_em, ota_0, ota_1, coredump
├── dependencies.lock          resolved managed components (espressif/led_strip 3.0.3)
├── cmake/cgw_component.cmake  compiler warnings of the project components
├── main/                      composition root: app_main, static tasks and queues, port bindings, Kconfig
├── components/
│   ├── cgw_ports/             port interfaces (header-only)
│   ├── cgw_proto/             APP protocol codec over gen/ (nanopb, generated)
│   ├── cgw_session/           [SEC] session table, handshake, tags, counters, rate limit
│   ├── cgw_pairing/           [SEC] pairing window, payload, passphrase
│   ├── cgw_arbiter/           [SAF] window press and door transaction state machines
│   ├── cgw_com/               [SAF] can_io logic over gen/ (cantools, generated)
│   ├── cgw_vstate/            vehicle state, StatusUpdate, push policy, version check
│   ├── cgw_health/            modes, DTCs, reset reasons
│   ├── cgw_core/              core active object (event dispatch, 10 ms time event)
│   ├── cgw_platform_esp/      AO runtime, clock, trace outputs, alive supervision, fault injection
│   ├── cgw_wifi_esp/          SoftAP
│   ├── cgw_ws_esp/            HTTP server, WebSocket endpoint, TX ring (link port)
│   ├── cgw_can_esp/           TWAI node, timing, filter, TX slots (CAN port)
│   ├── cgw_crypto_psa/        PSA Crypto: HMAC, HKDF, tags, RNG, known-answer tests
│   ├── cgw_store_nvs/         key store over NVS
│   ├── cgw_hmi_esp/           status LED, BOOT button, pairing QR printer
│   └── nanopb/ qrcodegen/     wrappers over third_party/
```

The core components (`cgw_proto`, `cgw_session`, `cgw_pairing`, `cgw_arbiter`, `cgw_com`, `cgw_vstate`, `cgw_health`, `cgw_core`) include no ESP-IDF headers and build on the host. `components/cgw_com/gen/` and `components/cgw_proto/gen/` are generated by `uv run tools/codegen/regen.py` and never edited.

## Build

Default build (common configuration, build type DEV without fault injection):

```sh
docker run --rm -e IDF_GIT_SAFE_DIR=/project -v "$PWD":/project -w /project/firmware/cgw \
  espressif/idf:v5.5.5 idf.py set-target esp32s3 build
```

Variants (run from the repository root):

```sh
# DEV: fault-injection console, comprehensive heap checks
docker run --rm -e IDF_GIT_SAFE_DIR=/project -v "$PWD":/project -w /project/firmware/cgw \
  espressif/idf:v5.5.5 idf.py -B build/dev -D SDKCONFIG=build/dev/sdkconfig \
  -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.dev" build

# RC and RELEASE: no fault injection, no console REPL
docker run --rm -e IDF_GIT_SAFE_DIR=/project -v "$PWD":/project -w /project/firmware/cgw \
  espressif/idf:v5.5.5 idf.py -B build/release -D SDKCONFIG=build/release/sdkconfig \
  -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.release" build
```

Release images must contain no `cgw_fi_` symbol (SWR-CGW-067):

```sh
xtensa-esp32s3-elf-nm build/release/locksys_cgw.elf | grep -c ' cgw_fi_'   # expected: 0
```

`PROJECT_VER` follows `VERSION`; `main/CMakeLists.txt` writes `ls_version_gen.h` (SemVer, short commit hash, dirty flag) into the build directory. `sdkconfig`, `build*/` and `managed_components/` are not committed.

## Host unit tests

```sh
tools/docker/ceedling/run.sh firmware/cgw/test/host test:all     # tests
tools/ci/ceedling_ci.sh cgw firmware/cgw/test/host                # tests, coverage and gate
```

The ports are replaced by fakes (`test/host/support/fake_ports.c`); the crypto port by a software HMAC-SHA256 and HKDF implementation. Session, codec and E2E tests compare byte for byte with `interfaces/vectors/app_session_v1.json` and `interfaces/vectors/e2e_v1.json`. Coverage is reported against the `cgw` scopes of `tools/ci/quality_gates.yaml` (report-only until the M3 exit).

## Configuration (Kconfig, menu "LockSys CGW")

| Option | Default | Meaning |
|---|---|---|
| `CGW_BOARD_REV` | v1.1 | Status LED on GPIO38 (v1.1) or GPIO48 (v1.0) |
| `CGW_BUILD_TYPE` | DEV | DEV, RC or RELEASE, transmitted in CGW_Version |
| `CGW_FAULT_INJECTION` | n | DEV only: console `fi core_hang`, `canio_hang`, `can_silent`, `e2e_crc`, `e2e_ctr`, `drop_stop`, `wifi_off`, `off` |
| `CGW_WIFI_TRANSITION` | n | DEV only: WPA2/WPA3 transition mode |
| `CGW_WIFI_CHANNEL`, `CGW_WIFI_COUNTRY` | 6, "01" | SoftAP radio |
| `LS_SOFTAP_OFFER_ROUTER` | n | Router option in DHCP offers |
| `CGW_CAN_TX_GPIO`, `CGW_CAN_RX_GPIO` | 4, 5 | TWAI pins |
| `CGW_TRACE_PINS`, `CGW_TRACE0..3_GPIO` | y, 7/15/16/17 | Trace outputs (all builds) |

## Pins

TWAI TX GPIO4, RX GPIO5 (acceptance filter 0x200–0x23F and 0x510/0x590); TRACE0 GPIO7 (RMT width-coded events), TRACE1 GPIO15 (STOP pending), TRACE2 GPIO16 (CGW_WinCmd enqueue), TRACE3 GPIO17 (core dispatch); status LED GPIO38; BOOT GPIO0 (pairing hold 5 s, factory reset hold 10 s, ignored for 2 s after boot). GPIO6 (CAN standby) and GPIO18 (self-test loopback) are reserved.

## Open points (M0)

| ID | Topic | Handling |
|---|---|---|
| CGW-M0-1 | TRACE0 frame events are emitted by the core when it handles the frame, not by the WebSocket handler; the handler-to-core latency is part of the TRACE0 offset | Measure against the ≤ 0.5 ms budget at M3; move into the handler if needed |
| CGW-M0-2 | SessionClose reasons: FAILED_TIMEOUT for a timeout, REJECTED_BUSY for a pre-emption, REJECTED_AUTH after a key-store fault; LS-SAIC-001 does not fix the values | Confirm in the contract |
| CGW-M0-3 | A plain HTTP GET to `/ws/v1` is answered by the ESP-IDF handshake code, not with an explicit 400 | Verify the response at M3 |
| CGW-M0-4 | Fault injections `e2e_crc`, `e2e_ctr`, `drop_stop` and `wifi_off` are recorded but not yet applied | M3 with the HIL procedures |
| CGW-M0-5 | Health metrics (heap, stack and queue high-water marks) are not yet logged; CGW_NodeSts carries the free heap percentage | M3 |
